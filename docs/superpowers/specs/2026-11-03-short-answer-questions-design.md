# 단답형 문제 설계

## 목표

서술형(시나리오형, 개념형)만 있는 앱에 용어나 한두 문장으로 답하는 단답형 문제를 추가한다. 추가 풀이, 문제 은행, 오늘의 문제에서 풀 수 있고, 모의 면접은 바꾸지 않는다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 구현 방식 | `format` 에 `short-answer` 를 추가하고 문제와 채점 결과 구조를 재사용한다. |
| 채점 | 기존 감독관 실행 경로로 LLM 이 정답, 부분 정답, 오답을 판정한다. |
| 총점 | `full` 100점, `partial` 50점, `missing` 0점. 관점 점수, 가점, 감점은 계산하지 않는다. |
| 오늘의 문제 | 기존 구성 뒤에 단답형 3문제를 항상 추가한다. 이미 만들어진 날짜의 세트는 바꾸지 않는다. |
| 힌트와 미루기 | 제공하지 않는다. 힌트 하나가 사실상 정답이 되기 때문이다. |
| 약점 복습 | 단답형은 대상에서 제외한다. 하루 3문제씩 쌓이는 오답이 서술형 복습을 밀어내지 않게 한다. |
| 채점 뒤 대화 | 꼬리 질문과 채점 질문은 그대로 유지한다. |

## 문제 구조

- `situation` 에 질문을 쓰고 `requirements` 는 비운다.
- `rubric.required` 는 1개이고, `rubric.bonus` 와 `perspectives` 는 비운다.
- `recommendedLength` 는 5~150자로 고정한다.
- `title` 은 정답을 드러내지 않는다.
- 유형은 `term-definition`(용어와 정의), `behavior-rule`(동작 규칙), `applied-judgment`(상황 적용) 3개다.
- LLM 이 다른 값을 돌려줘도 앱이 저장 전에 위 구조로 맞춘다.

## 오늘의 문제 선정

- 단답형 3문제는 서로 다른 주제에서 고른다. 활성화된 주제가 3개보다 적으면 주제가 반복될 수 있다.
- 주제 제외 규칙이 초기화되어도 같은 문제가 두 번 뽑히지 않도록, 이미 선택한 문제를 후보에서 뺀다.
- 은행에 맞는 문제가 없으면 기존 항목처럼 LLM 으로 생성한다.

## 화면

- 풀이: 질문, 짧은 입력창, 글자 수, 제출 버튼을 한 열로 보여 준다. 미리보기 탭과 힌트 패널은 없다.
- 결과: 총점과 판정, 해설을 보여 주고 관점 점수 영역은 숨긴다. 탭은 모범 답안, 내 답안 비교, 채점 상세, 추가 학습이다.
- 설정: "하루 문제 수" 를 "하루 서술형 문제 수" 로 바꾸고, 단답형 3문제가 별도로 나온다는 안내를 넣는다.

## 시드 문제

7개 주제에 유형별 1문제씩 21문제를 추가한다. 용어와 정의는 주니어, 동작 규칙은 미들, 상황 적용은 시니어로 둔다.

## 검증

`npm run typecheck`, `npm test`, `npm run validate:seed` 를 통과해야 한다. 사내 네트워크에서 npm 레지스트리가 차단되어 있으므로 GitHub Actions 의 `workflow_dispatch` 실행으로 검증한다.
