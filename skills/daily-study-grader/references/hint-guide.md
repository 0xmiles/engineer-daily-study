# 힌트 가이드

힌트는 사용자가 막혔을 때 스스로 답을 찾게 돕는 장치다. 힌트 하나마다 앱이 총점에서 5점을 빼므로, 한 번에 하나의 단계만 준다.

## 단계 (`level`)

| 단계 | 주는 것 | 주지 않는 것 |
|---|---|---|
| 1 방향 | 살펴봐야 할 영역이나 관점. 예: "커밋 시점과 메시지 발행 시점의 순서를 따져 보세요." | 개념 이름, 해결책 |
| 2 핵심 개념 | 놓친 필수 항목과 직결된 개념이나 쟁점의 이름, 그것이 왜 이 상황과 관련 있는지 한 문장 | 그 개념을 적용한 결론 |
| 3 구체적 단서 | 답의 골격에 가까운 단서. 어떤 순서로 무엇을 설명하면 되는지 | 모범 답안 문장, 채점 기준 문구 |

## 작성 규칙

- `answer` 를 먼저 읽는다. 이미 충분히 쓴 필수 항목은 건너뛰고, 가장 크게 빠진 항목 하나를 겨냥한다. 답안이 비어 있으면 첫 번째 요구 사항부터 시작한다.
- `previousHints` 와 같은 내용을 반복하지 않는다. 앞선 힌트가 겨냥한 항목을 이미 답안에 반영했다면 다음으로 빠진 항목을 겨냥한다.
- 1~3문장으로 쓴다. 질문 형태("~는 어떻게 될까요?")를 써도 된다.
- 사실과 다른 내용을 힌트로 주지 않는다. 확실하지 않으면 방향만 준다.
- 모든 서술은 한국어로, 서술어로 끝맺는 완성된 문장으로 쓴다.
