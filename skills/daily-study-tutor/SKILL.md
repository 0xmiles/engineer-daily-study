# Daily Study 학습 노트 skill

채점이나 모의 면접에서 "더 공부할 것"으로 추천되었거나, 문제 은행의 문제가 학습 주제로 꼽은 키워드 하나를 받아, 검색 없이도 핵심을 이해하고 면접에서 설명할 수 있을 만큼의 학습 노트를 쓴다.

결과물은 `schemas/study-guide.schema.json` 형식의 JSON 하나다. 작업 전에 `references/study-guide-guide.md` 를 읽는다. 요청 입력이 없으면(터미널에서 대화로 요청한 경우) 사용자가 말한 키워드로 같은 구성의 노트를 마크다운으로 쓴다.

## 입력

- `keyword`: 공부할 키워드. 예: "Kafka Consumer 리밸런싱 프로토콜".
- `topics`: 키워드가 추천된 문제의 주제(`value`, `label`, `description`). `description` 은 사용자가 직접 추가한 주제의 범위이고, 기본 주제는 비어 있을 수 있다.
- `recommendations`: 이 키워드가 추천된 기록. 최신순이다. 문제 은행의 문제만 이 키워드를 꼽았다면 비어 있다.
  - `from`: 추천된 곳(문제 제목 또는 모의 면접).
  - `difficulty`: 그 문제나 면접의 난이도(`junior`, `middle`, `senior`). 알 수 없으면 `null`.
  - `reason`: 감독관이 이 키워드를 추천한 이유. 사용자 답안에서 드러난 부족한 점이 담겨 있다.
  - `searchQuery`: 감독관이 제안한 검색어.
- `questions`: 이 키워드를 학습 주제로 꼽은 문제 은행의 문제. 비어 있을 수 있다.
  - `title`, `format`(`scenario`, `concept`, `short-answer`), `difficulty`: 문제 제목, 형식, 난이도.
  - `keyIssues`: 그 문제의 핵심 쟁점. `requiredPoints`: 채점에서 반드시 확인하는 항목.

## 절차

1. `reason` 을 모두 읽고 사용자가 무엇을 몰랐거나 잘못 알았는지 파악한다. 노트는 그 빈틈을 메우는 데서 시작한다.
2. `questions` 가 있으면 `keyIssues` 와 `requiredPoints` 를 읽고, 그 문제를 풀 때 이 키워드의 어떤 부분이 쓰이는지 파악한다. 노트는 그 부분을 빠짐없이 다룬다.
3. `recommendations` 와 `questions` 의 `difficulty` 중 가장 높은 난이도를 기준으로 깊이를 정한다. 기준은 `references/study-guide-guide.md` 를 따른다.
4. `topics` 의 맥락(예: Kafka 문제에서 나온 "멱등성"이면 Kafka 프로듀서의 멱등성)에 맞춰 키워드의 범위를 좁힌다.
5. 요약, 본문 섹션, 흔한 오해, 스스로 점검, 연관 키워드를 쓴다.

노트는 키워드를 공부하는 자료다. 문제의 답이나 모범 답안을 쓰지 않는다. 문제 상황을 예로 들 때도 그 문제의 결론을 밝히지 않고, 같은 개념이 쓰이는 다른 상황을 예로 든다.

## 출력 규칙

- 결과는 JSON 하나만 출력한다. 설명 문장을 앞뒤에 붙이지 않는다.
- 모든 서술은 한국어로, 서술어로 끝맺는 완성된 문장으로 쓴다. 기술 용어는 통용되는 번역어가 있으면 번역어를, 없으면 원어를 쓰고, 처음 나올 때 원어를 괄호로 함께 쓴다.
- 확실하지 않은 내용은 쓰지 않는다. 버전마다 다른 동작은 버전을 밝힌다.
