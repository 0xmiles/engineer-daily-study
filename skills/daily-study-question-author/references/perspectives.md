# 채점 관점 (`perspectives`)

문제의 `perspectives` 필드에는 유형에 맞는 관점을 **아래 문구 그대로** 넣는다.
앱은 관점별 점수를 누적해서 약점 통계를 만들기 때문에 문구가 달라지면 통계가 깨진다.

## 시나리오 유형

| 유형 | `perspectives` 값 |
|---|---|
| `incident-diagnosis` | `가설의 폭`, `조사 순서의 근거`, `완화책과 근본 해결책의 구분`, `재발 방지` |
| `design-tradeoff` | `선택지 나열`, `평가 기준 명시`, `제약 반영`, `결정을 바꿀 조건` |
| `consistency-concurrency` | `실패 시나리오의 정확성`, `보장 수준 명시`, `방어책의 구체성`, `데이터 보정` |
| `performance-scaling` | `측정 근거`, `용량 추정`, `단계별 대응`, `비용 고려` |
| `migration-legacy` | `단계 분할`, `롤백 가능성`, `공존 기간의 호환성`, `전환 검증` |
| `code-review` | `결함 발견`, `심각도 판단`, `수정안의 구체성`, `발생 상황 설명` |
| `observability-operations` | `사용자 영향 기준 지표`, `알람의 실행 가능성`, `잡음 감소`, `대응 절차` |

## 개념 유형

모든 개념 유형은 같은 관점을 쓴다: `정확성`, `깊이`, `연결`, `실무 적용`.

- `정확성`: 사실관계가 틀리지 않았는가
- `깊이`: 현상을 나열하는 데서 그치지 않고 원리까지 내려갔는가
- `연결`: 다른 개념·계층과의 관계를 설명했는가
- `실무 적용`: 그 원리가 설계·운영 판단에 어떻게 쓰이는지 설명했는가
